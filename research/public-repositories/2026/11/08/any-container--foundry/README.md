## README overview

Relational index of layers. A layer is one end-to-end feature implementation, committed together; its git commit SHA is its id.

Layer files use OKF v0.2 front matter. `type: Layer` marks a layer file; `layer`, `parents` and `siblings` are OKF extension keys.

layer: feature_registry        # layer name, required

parents: [other_layer]         # names; must already be registered (earlier commit)

siblings: [another_layer]      # names; must already be registered; one-way

generated: { by: human:thom, at: 2026-11-05T00:00:00Z }

Only files with `type: Layer` register. Payload files under `layers/ /rails/` are copied into host apps and carry no layer front matter. `children` is not written by hand; it is filled in when a child registers. A parent must be registered in an earlier commit than its child.

PRs labelled `layer` run `.github/workflows/create-layer.yml`. It runs `ruby register_layer.rb  `, commits `foundry.sqlite3` to the PR branch, and comments the short SHA with success or failure.

Local run: `gem install sqlite3 && ruby register_layer.rb`.

The script reads `layers/` in this repository's git history. Rows registered before the move from `any-container/rails-template` carry that repository's commit SHAs as ids.
