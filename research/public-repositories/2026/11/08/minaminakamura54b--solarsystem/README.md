## README overview

ドローンで撮影した太陽光パネルのサーモ（赤外線）画像から熱異常をスクリーニングし、発電所ごとの点検結果・アラート・売電実績を管理する Rails アプリケーションです。

> **移行中です。** 以前の「Claude に画像を見せて判定させる方式」（温度を測っていないため精度に根本的な限界がある）を、「放射温度データ ＋ ルール判定 ＋ 人の確認」方式に作り替えています。Claude は、人が確定した異常の所見と総括文を書くだけで、判定はしません。計画と仕様は docs/IMPROVEMENT_PLAN.md を参照してください。

発電所一覧の「実配置を登録」から、配置図から作った CSV を選び、確認画面で内容を見てから確定します。CSV は発電所の配置の全体で、この発電所のパネルを CSV の内容に置き換え、パネル枚数を CSV の件数にします。文字コードは UTF-8 か Shift_JIS、1 行目は列名です（英語・日本語のどちらでも可。雛形の CSV は英語の列名）。

- 実配置のパネルは、パネル番号が同じなら同じパネルとして更新します（状態・最終点検日時・異常との紐付けは残る）。仮配置のパネルは、番号が同じでも引き継ぎません

- 消えるパネル（仮配置と、CSV に無い実配置）に紐付いた異常は、パネルの割り当てを外して元のパネル番号を履歴に残し、「割り当て直しの一覧」に出します。レビュー画面のパネル選択で割り当て直します（確定・重大度は変わらず、レビュー完了済みの点検もレビュー待ちに戻りません。割り当ての変更は履歴に残ります）

確定・修正済みの異常は `bin/rails "dataset:export[/path/to/out]"` で YOLO 形式の学習データとして書き出せます（顧客の画像を含むため、リポジトリの外か `tmp/` に書き出してください）。

実際の R-JPEG の温度データの読み取り（DJI Thermal SDK）は Phase S の後に実装します（手順書は docs/PHASE_S_RUNBOOK.md）。点検詳細で、測定パラメータ（放射率・反射温度・距離。任意）を入力できます（湿度は気象データを使う）。それまでは、開発用の合成データ（下の「開発用の合成点検」）で動作を確かめられます。

旧方式（画像1枚を Claude に判定させる方式）で作った点検は、表示だけできます（判定の処理は Phase 6 で削除しました）。詳しい流れは docs/ARCHITECTURE.md を参照してください。

- フロントエンド: Propshaft、importmap、Turbo、Stimulus、Chartkick
