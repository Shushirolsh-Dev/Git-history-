## README overview

用純 Ruby 過濾 `.cin` 輸入法字典中「指定字體無法顯示的字符」，輸出乾淨的 `.cin` 檔。

- **零外部依賴**：只用 Ruby 標準庫（`optparse`、`set`），不需要 `gem install`，不需要 Python，不需要 `fontTools`。

- **直接讀字體 cmap**：自己解析 TTF / OTF / TTC 的二進位表，支援 `format 0 / 4 / 6 / 12 / 13`，涵蓋現行所有主流字體。

- **針對字體精準過濾**：判定標準與 `isittofu`、`gottrix` 等字體覆蓋工具一致 —— 字符的碼位在字體 `cmap` 中映射到非 `.notdef` 的 glyph，即視為「該字體支援」。

- **保留 CIN 結構**：正確處理 `%keyname` / `%chardef` 段落，空行、註解與元資訊原樣保留。

- **附帶診斷報告**：列出每個缺失字符的碼位、出現次數，以及被刪除的完整行，方便核對或改用覆蓋更廣的字體。

Android / Linux 系統的內建中文字體（例如 `NotoSansCJK-Regular.ttc`）雖然覆蓋了《通用規範漢字表》的所有漢字，但對於 **CJK 擴展 B、C、D、E、F、G、H 區** 的超生僻字支援仍不完整。

把一份包含幾十萬行候選的 `.cin` 字典（如 `uniliu.txt`）放進 Rime 或其他輸入法時，這些字體不支援的字符會在候選欄或上屏後顯示成 **豆腐塊 `□`**。雖然可以在輸入法前端用 Lua filter 動態過濾，但：

`cin_font_filter.rb` 選擇在 **字典層** 一次性處理：只要你指定目標字體，腳本就把所有「該字體無法顯示」的候選行刪除，產生一份對該字體「乾淨」的 `.cin`。適用於任何支援 CIN 格式的輸入法。

適用場景：某些字體實際上有中文字形，但 `cmap` 未映射到這些標點；若確定要保留，可用白名單強制放行。

> `.ttc` 通常包含多個字重（Regular / Bold / Light…），用 `--font-index` 指定要當作「顯示參考」的那一個。

- 讀取字體開頭，判斷是 TTF/OTF（`sfnt`）還是 TTC（`ttcf` 集合）。

1. Platform 0, Encoding 4/6（Unicode full repertoire）

2. Platform 3, Encoding 10（Windows full Unicode）

- 支援的 `cmap` 子表格式：**Format 0 / 4 / 6 / 12 / 13**（涵蓋所有現代字體）。
